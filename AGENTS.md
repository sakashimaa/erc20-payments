# Работа с erc20-payments

## Инструменты

- Используй Bun для запуска TypeScript, установки зависимостей и тестов. Для воспроизводимой установки выполни `bun install --frozen-lockfile`. Bun сам загружает файлы окружения.
- Запускай API через `bun run dev:api`. Для проверки изменений доступны `bun run typecheck`, `bun run lint` и `bun run test:unit`.
- Для интеграционных тестов подними PostgreSQL через `bun run test:infra`, затем выполни `bun run test:integration`. Этот скрипт загружает `.env.test`. Файл `tests/setup.ts` удаляет и заново создаёт указанную тестовую БД при каждом запуске.

## Устройство проекта

- В `src/api/index.ts` собираются зависимости. Передавай их в Hono через `createApp(deps)` и фабрики обработчиков, чтобы те же роуты можно было проверять в интеграционных тестах.
- Пути API определены в `src/api/routes`, обработчики в `src/api/controllers`, Zod-схемы в `src/api/validations`. Подключай аутентификацию и валидаторы перед основным обработчиком. Для запросов мерчанта бери идентификатор из `c.var.merchantId` после `requireApiKey`.
- Схема PostgreSQL находится в `src/db/schema.ts`. Существующее подключение использует Drizzle с адаптером postgres-js и преобразованием имён в snake_case. После изменения схемы генерируй миграцию через `bun run db:generate` и проверяй SQL в `drizzle/`.
- Используй `src/lib/hd.ts` для деривации адресов и `src/lib/crypto.ts` для шифрования. При расшифровке xpub передавай тот же контекст, что и при регистрации мерчанта, через `aadFor(merchantId, "xpub")`.
- При создании инвойса резервируй индекс и сохраняй инвойс через один объект транзакции. Суммы токенов передавай в PostgreSQL как десятичные строки в минимальных единицах токена.
